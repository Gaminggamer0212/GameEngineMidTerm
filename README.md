For OOP, I have used inheritance, abstraction, polymorphism, and encapsulation. The enemies and player is created to inherit a basecharacter script. The basecharacter abstracts the functions. Since you asked a new implemetation, I tried to make one which is the food that gets droped after an enemy gets killed by the bubble. Food is the base class and Apple and Pumpkin inherits food. I have not fully implemented it but if I have to there are probably more variables that has a protected modifiier which just only allows child classes to have access to the variable, which is encapsulation. Polymorphism one I tried to use for in the factory pattern so it spawns in food without knowing what it spcifically spawns. The implementation is very rushed so I didn't even test it.

For singleton, I have used it for the audio manager, this part of the answer will probably be the same as what I have said in the theoretical part of the exam. I used a singleton to ensure there is only one instance of the manager at one time. We don't want a random scripts to change the volume or just play whatever sounds from anywhere because it will cause problems like volume being unstable and sound modifiers not applying correctly.

I was not able to finish this part of the implementation. Essensially, the spawner does not care what food get spawned since there is a generic food class which apple and pumpkin inherits from.
